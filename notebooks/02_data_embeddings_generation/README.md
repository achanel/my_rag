# Chapter 2 — Data Collection, Embeddings & Augmented Generation

The three core pipeline stages: collecting/preparing source data, building
embeddings and storing them in a vector store, then augmenting generation
with retrieved context.

Source notebooks:
- [1_Data_collection_preparation.ipynb](https://github.com/Denis2054/RAG-Driven-Generative-AI/blob/main/Chapter02/1_Data_collection_preparation.ipynb)

Tools: Deep Lake (vector store), OpenAI API.

## Implementation

**Part 1 — DATA COLLECTION** is implemented in `my_rag/collection.py` instead
of a notebook. It mirrors the book's `fetch_and_clean`: download each Wikipedia
article with `requests`, keep only the `mw-parser-output` body, drop the
"References" / "Bibliography" / "External links" / "See also" sections, strip
citation markers, and write every article to one Markdown file as a `#` heading
(its Wikipedia title) followed by the article body.

```bash
python -m my_rag --collect                       # -> data/raw/llm.md
python -m my_rag --collect --output my_corpus.md
rm -rf data/raw/llm.md data/raw/my_corpus.md      # cleanup (part 2 re-collects)
```

The URL list is `my_rag.collection.WIKI_URLS`; call
`my_rag.collection.collect(urls, output)` to fetch a custom set — it returns a
`CollectionResult` with the written path plus any URLs that were skipped (one
dead page no longer aborts the run, unlike the book's script). Two book URLs
moved and now point at their current titles: *Juice (spacecraft)* →
`Jupiter_Icy_Moons_Explorer`, *CHEOPS (satellite)* → `CHEOPS`. The two
dependencies (`requests`, `beautifulsoup4`) are already on the core stack.

**Part 2 — Embeddings + vector store** is implemented in
`my_rag/embeddings.py` and `my_rag/vectorstore.py`. It mirrors the book's
`2_Embeddings_vector_store.ipynb` ("Embedding-Based Retrieval with Activeloop and
OpenAI"): read the collected corpus, split it into 1000-character chunks, embed
every chunk, and store the vectors with their text/metadata in an Activeloop Deep
Lake `VectorStore`. Retrieval embeds the query and searches the store.

Two deliberate substitutions:

- **Free, lightweight embeddings instead of GPT.** The book calls OpenAI's
  `text-embedding-3-small`. The default here is `all-minilm` (384-dim,
  ~45 MB) served locally by Ollama — the same all-MiniLM-L6-v2 family the book
  itself uses for its evaluation cell. Ollama exposes an OpenAI-compatible
  `/v1/embeddings` endpoint, so the same client works for both. Set
  `MY_RAG_EMBEDDING_MODEL` (or `--provider openai`) to switch; the two providers
  keep separate dimensions (Ollama `all-minilm` 384, OpenAI 1536) and a store
  built with one cannot be searched with the other.
- **Local Deep Lake path instead of `hub://`.** The book stores at
  `hub://denis76/space_exploration_v1` (an Activeloop account). This port uses a
  local dataset path (`data/processed/vector_store`), so no
  `ACTIVELOOP_TOKEN`/network is required.

```bash
python -m my_rag --collect                 # part 1: -> data/raw/llm.md
python -m my_rag --embed                    # part 2: embed it into data/processed/vector_store
python -m my_rag --embed --output my_corpus.md --vector-store /tmp/vs --chunk-size 500
rm -rf data/raw/llm.md data/raw/my_corpus.md /tmp/vs   # cleanup (keep the store for part 3)
```

**Part 3 — Augmented generation** reuses the existing pipeline with the vector
store as the retriever: the top matching chunk is appended to the query, and the
answer is generated by the configured LLM (the book uses `gpt-4o`; here the
default is local Ollama). The book's notebooks 2 and 3 are combined into one
`--rag embeddings` path:

```bash
python -m my_rag --rag embeddings "Tell me about space exploration on the Moon and Mars."
python -m my_rag --rag embeddings --show-context "Tell me about space exploration on the Moon and Mars."
rm -rf data/processed/vector_store          # cleanup: drop the Deep Lake store
```

`--show-context` prints the retrieved chunk(s) before the answer (the store's
`search` also returns each hit's similarity score through the API). The book's
formatted Markdown response and its TF-IDF / embedding cosine-similarity
evaluation cells are not ported — they are presentation and evaluation
scaffolding, not part of the three pipeline stages.
